# 逐回合实时事件（Live Events）

- Status: implemented（E1–E7 全落地，World v13；E1 见先前提交，E2 `aa508cd`、E3 `a369931`、E4 `5e08225`、E5 `e39bc7c`、E6 `5248002`、E7 `278bb3e`）
- Depends on: ADR 0025（本计划对应决策）、ADR 0003（引擎/LLM 边界）、ADR 0024（事件效果走配置块编译）、`engine/events.ts`（`applyEventOption` 结算路径）、`engine/ai.ts`（`$.model.complete` 调用风格）
- Scope: 在世界逐月推进之后，由引擎挑出显著题材、由 LLM 生成 0 至 2 个可交互事件，效果编译回既有事件结构并持久化。**不**引入持久国力状态，**不**是里程碑/成就系统。
- 来源：用户口述。目标是「逐回合的沉浸式交互事件」，让世界对刚变化的状态作出反应；「爽感」是副产品。

## 0. 现状诊断（已核实）

| 现象 | 事实 | 位置 |
| --- | --- | --- |
| 事件是固定模板 | `EVENT_TEMPLATES` 10 个模板，文本/选项/效果写死 | `engine/data.ts:1563` |
| 抽取是加权随机 | 每月 `0.055 + 激进/1200` 掷一次，模板按 `weight` 选 | `engine/events.ts:149`（`tickEvents`）、`engine/data.ts:1808`（`spawnEvent`） |
| 文本与状态脱节 | 模板文案对任何国家都通用，不读刚变化的具体数字 | 模板 `text(c)` 只做简单插值 |
| 两次月报之间静止 | 推进后只有月报，没有针对新态势的交互 | `hooks/register.tsx`（`advanceGame`） |
| 已有的异步 LLM 缝合范式 | 仲裁者用 `arbiterCompleter` 做一次廉价 `$.model.complete`，失败返回空串走确定性兜底 | `hooks/register.tsx:309` |

## 1. 目标与非目标

**目标**

- 每次 `advance` 之后，世界给出**本回合刚生成**的 0 至 2 个可交互事件，题材来自新状态的显著变化。
- 事件文本、选项与叙事由 LLM 撰写；效果数值经引擎校验后按既有结算路径落账。
- 生成结果写入 `world.events`，读档不重新生成，行为可复现。
- 生成阻塞但有限超时，失败或超时降级，推进永不因模型停滞。

**非目标**

- 不做多主体生成（各主要大国分别生成），留给后续切片（对应 0002 的多国交互）。**（后续切片 E5 已落地，见 §7。）**
- 不做三视角的硬结构，三视角只进提示词。**（E6 已落地；仍只进提示词，无硬结构。）**
- 不做持久国力/繁荣状态，不做里程碑或成就。
- 不对叙事真实性做输出校验。
- 不在本计划内退役旧加权随机抽取；先做新闭环，退役方式见 §10 待定。**（E1–E7 均未退役，仍作兜底。）**

## 2. 引擎缝合点（the seam）

沿用 `arbiterCompleter` 的形态新增一个生成器，插在 `advanceGame` 里 **`advance` 返回之后、`settleDueSituations` 附近、`setWorld` 与会议呈现之前**：

```
advanceGame($, months)
  └─ advance(world, months, decisions, rng)          # 确定性 tick，状态已更新
  └─ generateTurnEvents($, world)                    # 阻塞式生成；超时/失败降级
       ├─ scanSalientTopics(world)   → Topic[]        # 引擎：四维显著性扫描
       ├─ buildEventPrompt(world, topics)             # 引擎：状态 + 题材 + 三视角提示
       ├─ $.model.complete({ timeoutMs })             # LLM：一次调用，返回 JSON
       ├─ parseGeneratedEvents(text)                  # 引擎：解析 + 效果信封校验
       └─ compileEffects(option) → EventOption        # 引擎：编译/钳位/降级
  └─ world.events.push(...generated)                 # 持久化
  └─ 会议呈现（含本回合事件）
```

- 生成器签名参照 `arbiterCompleter($, world): (prompt) => Promise<string>`，但返回**已校验的 `GameEvent[]`** 而非原始文本，调用方拿到的是能直接入账的结果。
- 与仲裁共用同一个廉价模型档（`world.ai.model || 'haiku'`），最多一次调用（第一刀不做重试）。
- `advance` 保持纯确定性；生成是它之后的独立阶段，不改变 ADR 0003 的分工。

## 3. 题材模型

引擎对新状态做一次**只读**扫描，四个维度各产出候选题材，再按显著性排序取 1 至 2 个：

| 维度 | 读什么信号（示例） | 题材方向 |
| --- | --- | --- |
| 经济 | GDP 环比、逐建筑利润、粮价对基准的偏离、失业、贸易缺口 | 经济向 |
| 政治 | 合法性、激进、官僚效能、权威、债务压力档位 | 政治向 |
| 外交 | 关系漂移、恶名、战争与分数、禁运、敏感商品张力 | 外交向 |
| 民生 | 生活水平、识字率、城市化、饥荒门、就业基础 | 民生向 |

- **题材方向目录**：现有 10 个 `EVENT_TEMPLATES` 的 `kind` 映射到四个方向（例如丰收/饥荒/工业繁荣/经济萧条归经济向，革命浪潮归政治向，边疆危机/外交照会归外交向，生活水平相关归民生向），降级为「提示 LLM 往哪个方向写」的目录，不再直接产出固定事件。
- 第一刀（E2）只求「能选出 1 至 2 个显著题材」并产出稳定的种子对象；四维权重、阈值、去重规则先在 §10 标为待定，等基线试玩再定。

## 4. 效果信封：编译与校验

- LLM 输出的事件形如 `{ title, text, options: [{ label, result, effects }] }`，其中 `effects` 只能使用**既有字段**：`treasury / radicals / legitimacy / prestige / army / popsPercent / techPoints / relationTarget + relationAmount / succeed / modifiers[]`。
- 引擎复用 `applyEventOption`（`engine/events.ts`）落账；`modifiers[]` 经 ADR 0024 的配置块编译路径安装，`source` 前缀沿用 `event:<id>`。
- **边界与降级**：非有限数值、未知 stat、越界幅度一律**拒绝该选项**；整条事件若无可信选项则整体丢弃（宁愿 0 个事件，也不落一个坏事件）。
- 数量裁剪：每回合最多 2 个事件，按题材显著性取前若干。

## 5. 持久化与可复现

- 生成的事件进入 `world.events`（`GameEvent`：`id / date / kind / title / text / countryId / options / isResolved`），与现有事件同一数组、同一结算路径。
- **存档记录生成结果**：读档直接复用已存事件，不重新调用模型。这使 LLM 的非确定性被限制在「生成那一刻」，读档重放稳定。
- 事件 `kind` 使用题材方向或生成标签，便于日志与面板分类。

## 6. 托管轻量模式

- `months > 1` 的托管（`hooks/register.tsx` 的 `run` 路径）不得因每回合阻塞生成而变慢或卡住。
- 轻量策略：降低生成频率（例如每 N 月一次）或合并为一次批量调用；其余月份退回模板事件或空事件。
- 托管中若生成超时，静默降级，不触发 `councilInterrupt`（中断只保留给待决事件、新的战争、战争结束、秘书越权这些既有条件）。

## 7. TDD 里程碑

每个里程碑先写失败测试，再补实现；每个里程碑独立提交、测试全绿再进下一个。

| 里程碑 | 内容 | 行为 / 风险 | 护栏测试 |
| --- | --- | --- | --- |
| **E1 闭环（mock 模型）** ✅ | 缝合点 + 生成器骨架 + 解析 + 入账；模型用 mock 返回固定 JSON（`engine/liveEvents.ts` + `hooks/council.ts` 的 `generateTurnEvents`，测试见 `tests/live-events.test.ts`） | 把生成插进 `advance` 之后而不改变 `advance` 的确定性；阻塞位置错误会打乱会议呈现 | mock 返回 1 个事件 → `world.events` 出现 1 条；mock 返回空数组 → 0 条且不报错；`advance` 输出与接入前逐位相同 |
| **E2 题材显著性** ✅ | 四维扫描 + 排序 + 取前 1 至 2 + 题材方向目录（`aa508cd`） | 权重太敏感会刷屏；太迟钝仍死寂 | 造一个粮价/激进异常的世界，断言选出的题材命中对应维度；稳定世界选出 0 至 1 个；题材数 ≤ 2 |
| **E3 效果信封 + 边界** ✅ | 校验 + 编译 + 钳位 + 降级；数量裁剪（`a369931`） | 坏效果入账会污染世界；过度裁剪会吞掉正常事件 | 未知 stat / NaN / 越界 → 拒绝或降级；超量事件被裁到 2；合法效果经 `applyEventOption` 精确落账 |
| **E4 持久化 / 可复现** ✅ | 事件入 `world.events`；读档不重生成（`5e08225`） | 重生成会让读档行为漂移；存档膨胀 | 存档再读：事件一致且模型调用次数为 0；事件数组有上限（超限丢弃最旧） |
| **E5 多主体** ✅ | 各主要大国按各自视角分别生成（`e39bc7c`） | 调用数上升带来延迟与成本；跨主体题材需要去重 | mock 两国各返回事件，均正确入账且归属正确国家；单回合调用次数有明确上限 |
| **E6 三视角** ✅ | 史官 / 市井 / 列国舆论进提示词（无硬结构）（`5248002`） | 只影响提示词，不改变结算；不应引入新字段 | 提示词快照包含三视角引导；输出仍只走既有 `EventOption` 形状 |
| **E7 例行场景** ✅ | 日历式低频场景（约每年 1 至 2 次，可跳过）（`278bb3e`） | 频率过高会挤占主要事件；跳过语义要明确 | 一年内例行场景数落在 1 至 2；跳过不产生效果也不卡流程 |

## 8. 验收

- 一场 24 个月基线中，多数回合能读到与本回合状态相关的事件；事件数恒 ≤ 2。
- 生成超时/失败时推进正常完成，会议照常打开。
- 存档再读不重新生成，事件与效果一致。
- `claude plugin test .` 全绿、`claude plugin validate .` 通过。
- 不新增持久国力状态；除 `world.events` 外不引入新的世界状态字段（若必须新增类型字段，需先更新 ADR 0025 与 `types/index.d.ts`）。

## 9. 风险

| 风险 | 缓解 |
| --- | --- |
| 阻塞生成拖慢推进 | 有限超时；超时降级为模板或空事件；托管走轻量模式 |
| 每回合成本上升 | 每回合最多一次生成调用；托管降频/合并；共用 haiku 档 |
| 叙事与史实/状态不符 | 题材种子 + 状态快照收窄范围；**本决定有意不做输出校验** |
| 效果越界污染世界 | 效果信封校验 + 复算路径 + 坏事件整体丢弃 |
| 读档行为漂移 | 生成结果持久化，读档不重生成 |
| `world.events` 无限膨胀 | 事件数组设上限，超限丢弃最旧（与 `world.log` 的 400 行裁剪同思路） |
| 托管因生成卡住 | 轻量模式 + 静默降级，不触发中断 |

## 10. 待定

> E1–E7 已落地，下列条目按实现结果标注：**已定** 者给出落点；**仍待定** 者保留为后续试玩/清理项。

- **题材显著性权重**：**已定（E2）**。四维各取一个最强信号，按显著性降序取前 `LIVE_MAX_TOPICS`（=2），等分时保持 `LIVE_DIMENSIONS` 的稳定序；阈值常量集中在 `engine/config/events.ts`（`LIVE_*`），数值仍可随试玩微调。
- **超时值**：**已定**。生成调用 `timeoutMs = LIVE_EVENT_TIMEOUT_MS`（20000ms，`hooks/internal.ts`）；超时或失败降级为空事件，绝不阻塞推进。
- **每回合成本预算**：**已定（E5）**。`LIVE_MAX_SUBJECTS = 2`、`LIVE_MAX_MODEL_CALLS = 2`（每主体一次调用，硬上限 2 次），且每回合生成事件恒 ≤ `LIVE_MAX_EVENTS = 2`。
- **托管轻量策略**：**仍待定**。当前 `months > 1` 的托管**跳过**生成（`advanceGame(..., allowLiveEvents=false)`），跳过的月份退回空事件、绝不阻塞；是否改为「每 N 月生成一次 / 合并为一次批量调用」仍待定。
- **旧加权随机的退役**：**仍待定**。`tickEvents` 的概率与 `spawnEvent` 的 `weight` 目前仍作兜底保留，尚未退役。
- **多主体去重**：**已定（E5）**。`planLiveSubjects` 按「玩家优先 → GDP 降序 → id 破平」选主体，已被先前主体认领的题材键从后续主体剔除，无题材的主体直接跳过。
- **事件数组上限**：**已定**。沿用 `EVENTS_MAX = 80`，超限丢最旧（`hooks/council.ts`）。
