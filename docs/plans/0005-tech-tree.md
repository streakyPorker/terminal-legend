## 2. 研究机制

### 2.1 科技点产出

沿用现有公式：

```
pointsPerMonth =
  universities × 0.9 × (0.4 + literacy) ×
  (1 + education × 0.03) × (1 + era × 0.02)
```

- `techPoints` 修正仍然生效。
- 跨分支溢出与研究方向不改变点数总量，只改变流向。

### 2.2 选择节点

- 玩家/AI 选择一个**当前可研究**节点（前置满足、时代门槛满足）。
- 每月科技点流入该节点；完成后：
  1. 标记 `unlocked`；
  2. 应用该节点的永久修正；
  3. 记录编年史；
  4. `researching` 清空，等待下一次选择（AI 自动选下一项）。
- 未选择节点时，科技点不流失，暂存并显示“待选”。

### 2.3 国内跨分支溢出

- 主研究节点拿**全额**科技点；另外 `15–25%` 作为**额外进度**流入另外两条分支的当前时代节点（平均分配），不扣主节点。
- “当前时代节点”= 该分支中前置已满足、时代 ≤ 当前时代、尚未完成的第一个节点；没有可推进节点时，溢出暂存为 0（不跨分支囤积）。
- 溢出比例：

```
spillRate = clamp(
  0.15 +
  literacy × 0.10 +
  min(universities / 20, 0.10) +
  education × 0.01,
  0.15, 0.25
)
```

- `techPoints` 类 buff 影响总点数，因此也影响溢出量。
- 溢出只推进**已解锁前置**的节点；未解锁分支不接收溢出。
- 溢出进度不触发“完成”以外的额外奖励；完成时正常应用修正。

### 2.4 国际科技扩散

- 对每国计算伙伴中最高的科技分：

```
techScore(c) = era × 10 + unlockedNodes.length
gap = max(partnerScore) - ownScore
tradeShare = 该国与先进伙伴的贸易额 / 该国总贸易额
bonus = clamp(
  gap × 0.02 +
  tradeShare × 0.20 +
  relation / 1000 +
  (alliance ? 0.10 : 0),
  0, 0.50
)
```

- 研究速度 = `pointsPerMonth × (1 + bonus)`。
- 只对“落后国”生效（`gap > 0`）；不直接送点、不免费解锁。
- 贸易/关系/同盟数据来自 0004；没有贸易时退化为只按 gap/关系。
- 战争/禁运期间该伙伴的扩散加成归零。

### 2.5 溢出与 AI

- AI 选择节点时考虑：
  - 领袖特质（工业/贸易 → 工业；军事/扩张 → 军事；改革/务实 → 行政）；
  - 当前国情（工厂少 → 工业；激进高/合法性低 → 行政；战争/军队弱 → 军事）；
  - 时代门槛（优先补通用线）。
- 确定性兜底：按权重排序，取最高；同权重按节点 id 字典序，保证可复现。

## 3. 数据模型（World v13）

```ts
export type TechState = {
  /** 1..4 */
  era: number
  /** node id -> 0..1 progress */
  nodes: Record<string, number>
  unlocked: string[]
  /** node id, or '' when waiting for a choice */
  researching: string
  points: number
  pointsPerMonth: number
}
```

- 删除 `tech.level` 与 `tech.unlocked: string[]` 的旧语义；`unlocked` 改为节点 id。
- `TECH_NODES` 表驱动：`id, era, branch, name, cost, prerequisites, effects, unlocks?, year?`。
- **`tech.level` 的替代**：新增派生值 `techTier` 供旧公式使用：

```
techTier = 1 + era × 1.5 + unlocked.length × 0.05
```

  - 范围约 1–8，接近旧 1–10 级的生产乘数（`1 + techTier × 0.07`）。
  - 所有读 `tech.level` 的地方都要改为 `techTier` 或 `tech.era`：`engine/sim.ts`（生产乘数、威望、sol、城市化、科技点、战争强度）、`engine/thresholds.ts`、`engine/ai.ts`、`engine/secretary.ts`、`view/panels.tsx`、`view/format.ts`。
- **时代语义**：`era 1..4` 是**层级（Tier I–IV）**，不是硬性日历年；节点可带可选 `year` 作为历史节奏的软门槛。文档与 UI 使用“时代 I–IV”，避免与 1836/1850 年混淆；若启用 `year`，在节点上显示“最早年份”。
- 存档版本 **v13**；旧 v12 存档删除（ADR 0005）。
- UI/AI 的“科技等级”显示改为“时代 + 已解锁节点数”。

## 4. 效果与解锁

- 节点效果分两类：
  - **永久/限时修正**：走 `addModifier`，`source: 'tech:<id>'`；用于产出、税率、官僚、军力等。
  - **一次性效果（immediate）**：完成时直接改一次存量（如 `morale +5`、`radicals -2`、`legitimacy +3`），不产生永久流量。
- 遵守 ADR 0004 的存量/流量规则：不要把 `morale/loyalists/radicals/legitimacy` 的 flat 值写成永久修正，否则会变成每月流量并把数值推到上限；这类效果一律用 `immediate` 或限时修正。
- 新增 `navyStrength` 修正入口（与 `armyStrength` 并列），用于海军科技；不新增公式特判。
- `unlocks` 只写标记（如 `electrification`），本切片不新增建筑/商品；后续切片读取标记。
- 研究完成不消耗权威；科技不是政策，不进政策维护费。
- `addModifier` 的 64 条上限需要在 v13 提高（建议 128），或只淘汰限时/低优先级修正，避免早期永久科技被静默挤掉。

## 5. UI

- 科技页改为树：
  - 顶部：时代、科技点/月、当前研究、溢出比例、国际扩散加成；
  - 通用线一行；
  - 工业/行政/军事三列；
  - 每个节点：名称、时代、成本、进度条、效果、前置、状态（可研究/进行中/已解锁/锁定）。
- 节点点击/按钮切换研究目标；没有直接写状态的 UI 路径，仍通过 `v3_action research` 或面板处理器。
- 窄终端降级为单列列表；不新增页签。

## 6. 测试与验收

1. **节点解锁**：前置/时代不满足时拒绝；满足后可研究；完成后修正生效。
2. **跨分支溢出**：主研究 15–25% 流入其他分支；识字率/大学/教育提高比例；上限 25%。
3. **国际扩散**：落后国获得最高 +50% 速度；贸易/关系/同盟提高；战争/禁运归零。
4. **AI 选择**：同种子同国情选同一节点；人格/国情改变选择。
5. **120 个月基线**：科技进度有限、不越时代、不出现负成本/NaN。
6. **存档**：v13 读取；旧 v12 拒绝（ADR 0005）。
7. **渲染**：科技页在 terminal/desktop 可绘制。

## 8. 风险

| 风险 | 缓解 |
| --- | --- |
| 科技树内容量超出切片 | 第一版 16 节点；新建筑/商品延后 |

## 9. 待定（实施时再议）

- 新建筑/新商品解锁（原“科技效果 2”）的具体清单与时间。
- 科技点是否可来自贸易/外交（当前只来自大学/识字/教育）。
- 时代上限是否延伸到 1900（当前 1880）。
- 研究是否允许“暂停/切换”以及切换是否损失进度（建议允许切换，保留进度）。
