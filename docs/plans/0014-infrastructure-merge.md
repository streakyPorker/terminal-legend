# 基础设施建筑合并（infrastructure merge）

- Status: **proposed**（2026-10-22 试玩提出，后续再议）
- Depends on: `docs/plans/0011-building-expansion.md` F5（统一基础设施池）、ADR 0026
- 关联：`docs/plans/0013-construction-ui.md`（建造面板）

## 0. 背景

F5 把「交通基础设施」升级为**统一池**：铁路 / 港口 / 运河 / 电报分别**供给**，
全部建筑按 `infrastructureNeed` **需求**，`ratio < 1` 时对产出施加线性 debuff。

问题：四种建筑都在供给同一个池，但**造价、工程量、供给量各不相同**，玩家每次要手算
「每金净供给」才知道该建哪个。1836 试玩中，QING 的 ratio 从 1.10 一路跌到 0.79，
玩家问「再建多少才够、哪个值得」——说明**选择成本高于选择本身的价值**。

## 1. 需求

把 **港口 / 运河 / 铁路（是否含电报待定）合并为一类「基础设施」建筑**：

- 单一建筑、单一造价 / 工程量 / 建造点；
- 每座供给统一基础设施池（数值重新校准，使总供给与现四类组合大致相当）；
- 面板上只出现一个条目，**不再需要横向比价**。

## 2. 可选方案

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A. 完全合并 | 四类 → 一类 `infrastructure`，旧类型删除 | 需 world 版本 bump、种子重算、AI 建造逻辑改写 |
| B. 合并 + 升级档 | 保留一个建筑，内部有 港口→运河→铁路 三档升级 | 需建筑升级系统（当前没有） |
| C. 仅 UI 合并 | 数据仍是四类，面板折叠成一行并自动推荐 | 改动最小，但底层仍复杂 |

倾向 **A**（最简单、最符合「统一池」的设计意图），电报可并入或单独保留（信息属性另议）。

## 3. 开放问题

- 电报是否并入？它当前也供给 0.7/座，但语义是「信息」而非「运输」。
- 合并后是否保留地域约束（港口沿海、铁路内陆）？当前引擎没有地域模型。
- 种子与 AI：`COUNTRY_SEEDS` 的四类座数需按供给等价折算；AI 建造权重需重定。
- 世界版本 bump 与存档兼容（ADR 0005：不做兼容，可直接断档）。

## 4. 验收（草案）

- 1836 基线十国 `ratio` 与合并前相差 <5%。
- 面板只出现一个基建条目，造价/供给与旧组合的「每金净供给」最优者相当。
- `claude plugin test .` / `claude plugin validate .` 通过。
