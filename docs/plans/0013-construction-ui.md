# 建造面板：可建建筑清单 + x*y 下单（construction UI）

- Status: **done / implemented**（2026-10-22；引擎 `5f78f77`、UI `f390a14`；ADR 0027）
- Depends on: `docs/plans/0006-gm-engine-interface.md`（工具/面板分工）、`view/panels/`（S3 拆分后的面板布局）
- 关联问题：`docs/playtest-issues.md` **PT-037**（国有队列不暴露 `projectId`，无法取消）

## 0. 背景

试玩 QING 时，玩家需要反复通过 GM 用自然语言下建造单：

- 「兴建营造 5×1」「煤矿 1×5」「铁矿 1×5」——**“x\*y”= 每槽 x 座、共 y 个槽位**，必须
  **连调 y 次** `v3_action build { count: x }`；一次 `count=x*y` 会打包成单槽（>5 还会被拒）。
- 语义靠对话传达，反复误读（本局已误读两次），且**下单后无法取消**（PT-037），
  误操作的代价是锁死预算数个月。
- 结论：**建造这件事不该走自然语言**，应在面板上直接操作。

## 1. 需求

在面板的 **「国有建造队列」区块下方**，新增 **「可建建筑」清单**：

1. **列出全部 22 类建筑**（farms … workshops），即使当前存量为 0 也要列出。
2. 每行至少显示：
   - 建筑名、当前存量
   - 单座工程量（点）、单座月度建造点需求、`CAPACITY_COST`
   - **总造价预览**（工程量 × 0.2 金/点；注意与 `v3_inspect buildings` 的「造价/座」区分）
   - 当前市价与单座经营利润（可选，取自 `buildingProfits`）——帮助判断该建什么
   - `unlock.techLevel` 门槛（当前全为缺省，未来 plan 0005 会用到）
3. **x\*y 直接下单**：
   - 在行内选择 **x（每槽座数 1..5）** 与 **y（槽位数）**，或直接键入 `x*y`
   - 实时预览：**总工程量、总造价、预计工期（按当前闲置建造力）、每月现金支出**
   - 确认后等价于**连下 y 次** `v3_action build { building, count: x }`（每次一个槽）
   - 资金/建造力不足时给出警告而非静默失败
4. **队列区块**补齐可操作性：
   - 每个国有条目显示 **`projectId`**、类型 × 座数、剩余工程量、进度、预计回合
   - 提供 **取消** 入口（`v3_action cancel`）——同时修复 PT-037 的 GM 侧缺口
5. **队列编排（2026-10-22 试玩新增需求）**：
   - **插队**：新订单可指定插入位置（**队首 / 队尾 / 某条目之前或之后**），
     例如「基建插队」把港口、铁路排到矿厂之前；
   - **任意重排**：队列条目可**上移 / 下移**，改变建造顺序；
   - 引擎语义不变——队列仍按条目顺序分配建造力，UI 只负责编排，**不改引擎分配逻辑**；
   - GM 侧对应：`v3_action build` 增加 `position` / `before` 参数，并新增
     `v3_action reorder { projectId, position }`（须与 PT-037 的 id 暴露一起做）。
6. 输入控件需适配终端 UI：优先 **按键 + 数字/序号**，不依赖自由文本输入；
   与现有 `ControlAction` / `CouncilAction` 的按钮机制保持一致。

## 2. 不在本次范围

- 私人建造队列的交互（私人项目本就不可取消，ADR 0017）。
- 建筑升级/拆除。
- 科技门槛的实际生效（plan 0005）。

## 3. 验收

- `view/panels` 渲染测试：22 类建筑全部出现在清单中；队列条目显示 id 与进度。
- 交互测试：选 `1*5` 下单后，队列出现 **5 个**条目，每个 `count=1`（不是 1 个 `count=5`）。
- 预览数字与引擎实际扣款一致（工程量 × 0.2）。
- 取消入口能撤销国有条目（PT-037 收敛）。
- 插队测试：新条目插入队首后，建造力优先流向它，预计回合相应缩短。
- 重排测试：交换两条目后，`v3_inspect construction` 的顺序与 UI 一致。
- `claude plugin test .` / `claude plugin validate .` 通过。

## 4. 开放问题（已解决，2026-10-22 实现时定稿）

- **x、y 的上限**：`x`（每槽座数）沿用工具上限 **1..5**（`MAX_BUILDINGS_PER_SLOT`）；
  `y`（槽位数）设上限 **10**（`MAX_SLOTS_PER_ORDER`），防误下大单。面板仅提供 `1×1` / `5×1`
  两个便捷按钮 + `⇤1×1` 队首插单，未做自由文本框。
- **清单展示与分组**：**按 6 族分组**——采掘（农场/煤矿/铁矿/伐木场）、轻工（纺织/家具/酿酒/奢侈）、
  重工（机械/钢铁）、服务（学校/大学/官署）、军事（兵工厂/兵营/要塞/船坞）、基建（铁路/港口/
  运河/电报/营造所）；每行显示当前存量、单座工程量/月度建造点/造价、**单座经营利润**
  （取自 `buildingProfits`，绿/红着色）与未解锁科技门槛（前向占位）。
- **与秘书委托的边界**：秘书**不通过该 UI 下单**——建造面板是玩家侧交互；`v3_control`/面板写操作
  在托管进行中一律拒绝，秘书的授权范围不含队列编排。
- **插队的边界**：可以把条目移到**正在施工的条目之前**；**保留已投入进度**——`reorder` 用
  `splice` 取出再插回**同一个项目对象**，`progress`/`startedAt` 不退回、不重算，只改它后面的
  建造力分配次序。

实现与后续：ADR 0027；PT-037 收敛于 `5f78f77`（引擎暴露 `#index`/`id`、`cancel` 按 `projectId`
或 `index`、`build position/before`、`reorder`）与 `f390a14`（共享 `ConstructionPanel` 挂上御前
与经济面板）。
