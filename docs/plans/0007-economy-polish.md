## 1. 目标与非目标

**目标**
- 任意一个月都能用账本解释：收入、支出、贸易缺口、净资产变化各是多少，为什么。
- 贸易存在分工：至少农产品有双向流；大清能靠出口或进口替代维持支付能力。
- 建造队列可预期：每个项目有明确的月拨款、进度与预计完工月，不出现永久 0%。
- 科技与劳动力有节奏：4 所大学时 1→2 不超过 24 个月；失业指标与利用率口径一致。

**非目标（本期不做）**
- 多国交互事件树、局势/仲裁扩展（0002 暂停）。
- 科技树 v8（0005 等 E5 校准后再做）。
- 新增商品、新战争目标、新外交动作。

## 2. 工作包

### E1 世界贸易校准（P0）

- **诊断测试**：跑 24 个月，逐商品统计全球 bid/offer；断言关键商品每年至少出现一次 bid 和一次 offer；大清至少有一个月出口 > 0。
- 可选手段（成本从低到高）：
  1. 调国家种子：减少各国农场数、提高城市人口与消费需求；
  2. 调农场产出 / 粮食需求参数；
  3. 引入“世界其余地区”外部需求（按价格弹性吸收过剩农产品）；
  4. 让 AI 国家按比较优势专业化（少种粮、多建工厂）。
- **目标指标**：粮食全球 bid/offer 比 > 0.2；大清第 12 月出口收入 ≥ 5 金/月。
- **第一轮（32e624b，已完成）**：
  - 农场粮食 1.05 → 0.30、农场木材 0.16 → 0.04、矿场木材 0.06 → 0.04；
  - 工厂机械 0.09 → 0.18；
  - 工厂消费粮食（每座 ×1.0），让工业国成为粮食买家；
  - `SENSITIVE_DRAG` 7 → 15，抵消新贸易结构对鸦片危机关系条的稀释。
  - 结果：24 个月基线中粮食 bid 24/24、机械 offer 24/24、大清出口 24/24；84 个月国债 < 1000；新增 `tests/economy-calibration.test.ts`，173 项测试全绿。
- **第二轮已办（B5-r2，plan 0008 §5）**：成衣、酒、家具转为**真双向**全球贸易（工厂侧配方缩放 + 消费品需求侧重定，不动手工匠）；军械仍单侧，记为唯一非双向商品。详见 `docs/plans/0008-economy-remake.md` §5/§6 与 `docs/playtest-issues.md` PT-002。

### E2 贸易与支付能力可见化（P0，依赖 0006）

- 已完成：私人进口逆差已从国库剥离（ADR 0008），`v3_status` 显示“私人部门贸易逆差 + 私人外债”；双向关税与税后到岸价已实现（ADR 0009）。
- `v3_inspect trade`：双边流、进口账单、出口收入、关税、支付能力分解（出口 + 私人资本 + GDP×3%）、贸易缺口。
- `v3_forecast`：下月预测，并标注瓶颈是现金、建设预算还是支付能力。
- HUD / AbovePrompt 显示贸易缺口与支付能力，推进前给出警告。
- **验收**：玩家不读存档即可解释上月净资产变化。
- **已办（2026-10-22，`58e3e7b`）**：**PT-040 / PT-041 / PT-042** 三条显示口径问题一并修复——
  `v3_inspect market` 改显示 产出/进口/出口/**有效供给**并按有效供给判状态（PT-040）；
  `v3_inspect economy` 改读**结算快照**，NX 接入贸易、`C+I+G+NX = GDP`、与 `v3_status` 一致（PT-041）；
  `economy`/`market`/`fiscal` 分区注明「结算快照」，`fiscal` 税基行显示
  `税基量 × 税率 × 征收效率 = 税额`，`v3_status` GDP 行补上净出口（PT-042）。
- **待办（P0，PT-040，2026-10-22 试玩发现）**：`v3_inspect market` 的产出/需求/状态
  **未计入进出口**——价格引擎已按「国内产出 + 进口」定价（煤 30.5 vs 需求 57.6，
  进口约 31，价格 1.63 ≈ 基准 1.6），报表却只报国内口径并打出「短缺」，**自相矛盾**，
  直接误导建造与贸易决策。修法：每行增加 **进口 / 出口 / 有效供给**（产出 + 进口 − 出口）
  三列，状态标记改用有效供给；补渲染测试。属**显示口径修复，不动价格公式**。
- **待办（P0，PT-041，同源）**：`v3_inspect economy` 的 **GDP 未扣净出口**——
  显示「GDP 692.7 = C + I + G + 净出口 **+0**」，而 `trade` 的净出口是 **−48**；
  按贸易反推 GDP 应约 644.8，与 `v3_status` 的 646.9 吻合。修法：economy 的 `净出口`
  接入贸易结算，并注明分区是「结算快照」还是「实时」。**与 PT-040 同属 E2 可见化。**

### E3 建造队列公平与可见（P1）

- 现状：按 `monthsLeft` 排序，长工期项目（铁路）长期拿不到钱。
- 备选方案：
  - A. 按入队顺序（玩家优先级）；
  - B. 按 `monthlyCost` 比例分配预算；
  - C. 每项保留最低拨款，余额按比例分配。
- 状态与面板显示：本月预计拨款、进度、预计完工月、是否因现金暂停。
- **测试**：现金紧张时每项要么有非零进度，要么明确标记“暂停”，不允许静默饿死。

### E4 GDP 与账本一致性（P1）

- 已完成：净资产变动 = 收入 − 支出（私人逆差不再扣国库，ADR 0008）；双向关税按税后到岸价结算（ADR 0009）。
- 确认当月建设支出进入 I；私人建设与国有建设分开显示；C+I+G+NX 必须等于 GDP。
- 若保留一个月滞后，状态里明确写“本月 I 来自上月建设拨款”。
- **测试**：I 与建设支出同阶；GDP 分量求和等于 GDP。

### E5 科技与劳动力节奏（P1）

- 科技：目标“4 所大学时 1→2 ≤ 24 个月”；调整基础点数或科技成本。
- 劳动力：统一 `unemployment` 与 `laborRawUtilization` 口径；城市化 pull 提到可感知量级。
- **测试**：24 个月至少升 1 级科技；工厂数增加时失业率下降。

### E6 债务压力与赤字建设（已完成，ADR 0007）

- 小幅负净资产不再冻结国有建设；现金上限改为 3× GDP 重组底线。
- 债务/GDP ≥ 25% 起施加连续 debuff：收入、建设速度、合法性目标、月息加成，随比例加重。
- `v3_status` / HUD / `FiscalLedger` 暴露债务压力比例与四项惩罚。
- **测试**：`tests/debt-pressure.test.ts`（阈值、单调性、赤字建设）。

### E7 建造能力：营造所与队列槽位（已完成，ADR 0010）

- 新增「营造所」：消耗木材/粮食/铁，产出建造点；缺料会降低产出。
- 每槽最多 30 座（PT-112）；项目有工程量（单座月度建造点×30），工期 = 剩余工程量 ÷ 每月实际投入；
  每点造价固定 0.2 金，建筑乘数/加数 v1 为 1/0；每月订单不限量（ADR 0012、ADR 0013）。
- 不设每槽月度点数上限：国有队列按入队顺序取用闲置建造力，每个 entry 可拿
  `min(剩余建造力, 剩余工程量)`；私人自建 50%，可租用国有闲置点（0.3 金/点）。
- 状态、面板与队列分栏显示建造能力、队列剩余工程量/分配/闲置、私人建造。
- **测试**：`tests/construction-capacity.test.ts`（产出/缺料、队列顺序、槽位上限、私人租用、旧档归一）。

### E8 劳动需求乘以利用率（已完成，`d346b12`）

> **已落地（2026-10-22，`d346b12`）**：`deriveLabor` 逐类累加 `labor × count × utilization`，
> `utilization` 取**上月存储值**（与产出门控同一字段、同一滞后，ADR 0022）。全行业 `utilization = 1`
> 时**逐值等于**旧 `Σ(labor × count)`（不变量）；闲置/亏损行业释放劳力，失业因此获得**行业来源**。
> `v3_inspect labor` 新增「部门来源」行，列出闲置部门与其释放的劳力。纯派生口径，**World 仍 v12**。
> 新增测试 `tests/labor-utilization.test.ts`（不变量、减半、闲置抬高失业、inspect 覆盖）。以下为原始需求。

- **改前（E8 前）**：劳动需求 = `Σ(labor × count)`，**不含 `utilization`**。工厂闲置、利润转负时，
  用工仍按满座计入，**利润不会传导到就业**（手册 §7；`v3_inspect labor` 只给总量）。
- **需求**：改为 `Σ(labor × count × utilization)`，`utilization` 取**上月存储值**——与产出
  门控同一字段、同一滞后（ADR 0022）。
- **效果**：亏损/闲置行业立刻释放劳力 → **失业有了行业来源**；与现有
  `utilization`（亏损门控、下界 0.5、一阶平滑 0.25）天然咬合，无需新字段。
- **影响面**：`deriveLabor` / `v3_inspect labor` / 失业派生 / 就业基础展示；纯派生口径，
  **世界版本不升**。
- **测试**：
  - 全行业 `utilization = 100%` 时与旧口径**逐值一致**（不变量）；
  - 单行业 `utilization` 降至 0.5 时，其劳动需求相应减半；
  - 亏损类目闲置时失业率上升、`labor` 分区可见缺口来源。
- **关联**：ADR 0022、手册 §4.4 / §7；本局试玩（1836.11，大清失业 21%）。
