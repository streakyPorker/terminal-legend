# 双向关税：出口国出口税 + 进口国进口税，到岸价按真实税后价格

- Status: accepted（World v7，语义调整，不升版本）；“进出口同税率”部分由 ADR 0014 修订

## 背景

旧模型只有一个 `tariff`，且只在进口国一侧征收：

```
landed = 出口国国内价 × (1 + 进口国关税) × 运输/接入/风险
```

出口国不征税，玩家也无法通过出口税获得收入。更关键的是，贸易清算、支付能力与实际金币
结算都基于“国内价”，关税只作为进口国的一笔附加收入，价格并不是买卖双方真正面对的价格。

试玩反馈：

1. 默认关税不应为 0，应有 5% 左右；
2. 进出口都能收税；
3. 价格必须是“出口国出口关税 + 进口国进口关税”之后的真实价格。

## 决定

### 1. 一个税率，双向征收

- `Country.econ.tariff` 同时作为**出口关税率**与**进口关税率**；不新增字段。
- 出口关税 = 出口国国内价 × `tariff`。
- 进口关税 = 边境价 × `tariff`，其中边境价 = 国内价 + 出口关税。
- 到岸价（用于伙伴排序）：

```
landed = 国内价
       × (1 + 出口国 tariff / 100)
       × (1 + 进口国 tariff / 100)
       × 区域运输 × 市场接入 × 交通 × 关系风险
```

### 2. 结算拆分

对每一笔 `from → to` 的流量：

| 项目 | 公式 | 归属 |
| --- | --- | --- |
| 出口国私人收款 | `value = qty × 国内价` | 出口国私人资本 |
| 出口关税 | `value × 出口国 tariff` | 出口国国库 |
| 边境价 | `value + 出口关税` | 进口国私人支付 |
| 进口关税 | `边境价 × 进口国 tariff` | 进口国国库 |
| 进口国私人总支付 | `边境价 + 进口关税` | — |
| 关税总收入 | `出口关税 + 进口关税` | 各国国库，计入收入 |

- `TradeFlow` 新增 `exportDuty`；`tariffPaid` 仍表示进口国收取的进口税。
- `settleTrade` 返回 `importDuty`、`exportDuty` 与合计 `tariffRevenue`；
  `externalNet = exportRevenue − importBill − importDuty`（出口税已含在 `importBill` 里）。
- 软容量与支付能力按“进口国私人总支付”计算，不再只看国内价。

### 3. 默认与自由贸易

- 自由贸易法案把税率降低 8 个百分点，但**下限 5%**；不再降到 0。
- 当前 `tariff` 同时影响进出口，`v3_action tariff` 调整的就是这个双向税率。
- 国家种子的初始关税保持不变（大清 8%、英国 5%、法国 12% 等）；自由贸易后大清落到 5%。

## 理由

- **价格真实**：伙伴排序与结算使用同一个税后价格，避免“排序用税后、结算用税前”的错位。
- **财政对称**：出口国也能从出口征税，重商主义/出口导向政策有直接收入。
- **可解释**：玩家看到 5% 关税，知道进口和出口都被征了一次，国库的“关税”是两者之和。
- **不改存档**：`tariff` 字段已存在，`TradeFlow` 是月度瞬时结构；World 版本不变。

## 代价

- 同一税率双向征收，不能单独设置出口/进口税率；后续若需要，可加 `exportTariff` 字段并升版本。
- 到岸价上升（5% × 5% ≈ 10.25% 总量），贸易量会略降；自由贸易的收益更多来自市场接入与收入 +8%，而不是零关税。
- 进口国的私人支付、支付能力与软容量都要按含税价计算，相关测试已同步。
