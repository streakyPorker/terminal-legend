# AI 生成的逐回合事件

- Status: proposed（待用户批准实现）
- Depends on: ADR 0003（可计算的部分交给引擎，不可计算的部分交给 LLM）、ADR 0024（配置块，事件效果编译路径）、`docs/plans/0002-agent-event-trees.md`（暂停的前身）
- Scope: 把每月一次的固定事件模板换成**逐回合、由 AI 生成、可交互**的事件；实现切片见 `docs/plans/0010-live-events.md`。

## 背景

现状在 `engine/events.ts` 与 `engine/data.ts`：`EVENT_TEMPLATES` 有 10 个固定模板（丰年、饥荒、工业繁荣、经济萧条、革命浪潮、边疆危机、技术突破、领袖病重、殖民地动荡、外交照会）。每月 `tickEvents` 以 `0.055 + 激进/1200` 的概率掷一次，模板内再按 `weight` 加权，文本、选项与效果全部写死在表里。结果是同一批事件反复出现，世界在两次月报之间基本静止，玩家读到的常是模板腔。

用户要的是**逐回合的沉浸式交互事件**：每次推进之后，世界对**刚刚变化的状态**作出反应，给出值得读、值得选的事件。**爽感是副产品，不是目标**。这不是里程碑或成就系统，也不引入任何持久的「国力/繁荣」状态。判断与叙事归 LLM，数值与结算归引擎（ADR 0003）。

## 决定

1. **多阶段流程**：`advance`（确定性引擎 tick）→ **阻塞式事件生成**（LLM）→ 御前会议交互。生成调用在 `advance` 返回之后、会议呈现之前**同步**发生，因此会议里看到的事件一定是本回合刚生成的。
2. **题材种子**：引擎对新状态按**经济 / 政治 / 外交 / 民生**四个维度扫描，按显著性排序，产出 **1 至 2 个「显著题材」** 作为种子，与当前状态一并交给 LLM。现有 10 个 `EVENT_TEMPLATES` **降级为「题材方向」目录**（经济向 / 政治向 / 外交向 / 民生向），不再是固定事件；具体事件由 LLM 撰写。
3. **生成方式：混合**。引擎给题材种子，AI 展开。**第一刀只做单闭环**（引擎种子 → 一次生成调用 → 0 至 2 个事件）；多主体（各主要大国分别生成）是后续切片。
4. **数量**：每回合 0 至 2 个事件，按显著性取前若干，多余的丢弃（防刷屏）。
5. **效果信封**：叙事文本自由，但每个事件的**效果必须编译到既有的效果结构**（`EventOption.effects`：treasury / radicals / legitimacy / prestige / army / popsPercent / techPoints / relation 与 `modifiers[]`），由引擎校验并设边界（复用 `applyEventOption` / `settleEvent` 结算路径）。非法效果直接拒绝或降级。
6. **持久化与确定性**：生成的事件写入 `world.events`（文本、选项、效果）；存档记录生成结果，读档**不重新生成**（可复现）。LLM 是判断层（ADR 0003），引擎负责存储它的输出。
7. **阻塞与兜底**：同步调用带有限超时；超时或失败时降级为模板事件或空事件。托管游玩（`months > 1`）走轻量模式（减少调用 / 合并调用），不会卡住时间推进。
8. **三种旁白视角**：史官（朝廷编年）、市井（街头百姓）、列国舆论（他国观感）。三者**只作为提示词引导**，AI 自行决定如何使用，不设硬结构。
9. **现实主义：只靠提示词**。真实感由提示词引导，**不对叙事真实性做输出校验**。
10. **例行场景：后续切片**。保留低频的例行场景（日历式，约每年 1 至 2 次，可跳过）。

## 与 ADR 0003 的边界

本决定不改变 ADR 0003 的分工，只是把它用在「逐回合事件」这个新位置上：

- **LLM 产出**：题材相关的标题、正文、选项标签、结果叙述、以及每个选项的效果数值与限时修正。它只写 `EventOption` 形状的数据，不直接写世界状态。
- **引擎产出**：题材显著性扫描、数量上限裁剪、效果结构校验与钳位、结算（`applyEventOption`，经 ADR 0024 的配置块编译 `modifiers`）。
- **存档**：`world.events` 是生成结果的唯一事实来源。因为生成结果被持久化，LLM 的**非确定性被限制在「生成那一刻」**，读档重放得到同一批事件与同一套效果。

## 代价

- **关键路径上的 LLM 延迟**：生成是阻塞的，推进会等模型返回。用有限超时封顶，超时即降级；`$.model.complete` 在途调用不计入 hook 自身预算，但用户仍会感到等待。
- **每回合成本**：每个玩家回合一至两次模型调用（生成 + 可能的重试）。托管模式需要轻量策略控制调用次数。
- **非确定性被持久化收容，但未消失**：同一种子在不同存档里可能生成不同事件；可复现性只在「已落盘的结果」意义上成立，不保证「同种子必出同一事件」。
- **仅提示词约束的现实主义有风险**：模型可能写出与史实/世界状态不符的叙事。本决定**有意不做输出校验**，只靠题材种子与提示词把范围收窄。
- **题材显著性权重需要校准**：太敏感会刷屏，太迟钝则世界仍然死寂；权重先落一版，再按试玩调整。

## 暂不覆盖

- **多主体生成**：各主要大国由各自的领袖视角分别生成事件（对应 0002 的多国交互）。
- **三视角的硬结构**：目前三视角只进提示词，是否给 UI 分区、是否按事件类型固定配比，未定。
- **例行场景**：日历式低频场景的触发与呈现，留作后续切片。
- **题材显著性公式细节**：四维度的具体权重、阈值、去重规则，见 `docs/plans/0010-live-events.md` §10 待定。
- **旧加权随机抽取的退役**：`tickEvents` 的 `0.055 + 激进/1200` 概率与 `spawnEvent` 的 `weight` 掷骰如何被取代（保留为兜底还是彻底移除），见计划待定项。
