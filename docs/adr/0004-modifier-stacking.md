# 修正（buff/debuff）通过统一入口叠算

- Status: superseded by `0024-config-and-modifier-blocks.md`（叠算顺序原样保留并折入 0024；本文的存量/流量口径与来源审计继续有效）

所有可被政策、法案、事件或天命改变的数值，都必须经过 `engine/modifiers.ts` 的
`applyModifiers(country, stat, base)` 读取，而不是在公式里直接写死加成。修正带有
`id`、`label`、`stat`、`stack`、`value`、`monthsLeft` 与 `source`，按国家保存在
`country.modifiers` 中。

叠算顺序固定为：

```
(base + Σflat) × (1 + Σpercent / 100) × Π(1 + multiply / 100)
```

- `flat`：绝对值相加，适合「+2 点合法性」这类效果。
- `percent`：百分比相加成一个乘数，适合同类政策叠加（+10% 与 +20% 得 +30%）。
- `multiply`：独立乘数逐个相乘，适合稀有、会互相放大的效果。

同 `id` 的新修正覆盖旧修正（政策重提、事件重复触发不会无限叠加）；`monthsLeft`
在每月结算末尾递减，归零时从列表移除并写入编年史；未给 `monthsLeft` 的修正是长期
的，直到被显式移除。

**存量与流量**：修正作用在公式读取的那一层。派生量（生活水平、失业、合法性目标、
威望、生产、收入、支出、官僚效能等）修正最终水平；增量型存量（激进、忠诚、士气、
识字、权威、人力、人口增长）修正的是**当月流量**，避免百分比修正对存量每月复利。
例如「激进 −20%」表示每月激进增长减少 20%，而不是把激进值每月乘 0.8。

**来源**：同一套修正可以由五种来源产生，全部带 `source` 便于审计与移除：

- **事件**：`EventOption.effects.modifiers`，在选项结算时安装。
- **政策**：`v3_policy` / `applyPolicy`，LLM 提交效果条目，引擎校验并消耗权威（ADR 0002/0003）。
- **法案**：`applyDecision('law')` 的闭包直接 `addModifier`。
- **阈值**：`engine/thresholds.ts` 的状态规则；`while` 规则在条件消失时自动移除，`once` 规则永久保留。
- **天命**：`v3_cheat modifier`，供试玩与调试。

后续的国家专属国策/事件树只需向这些入口提交数据，不应在公式里写特判。

原因：buff/debuff 是玩法核心。如果每个公式各写各的加成，后续政策、贸易与外交切片会
不断改公式并产生叠加顺序歧义；统一入口让新效果只新增数据，不动引擎。

代价：公式可读性略降；每个新数值入口都要先声明为 `ModifierStat`，并决定它读取的是
原始值还是派生值。当前接入的入口见 `ModifierStat` 类型：生产与需求（均含每种商品）、
农业/矿业/工厂产出、国内生产总值、收入、
支出、税收效率、识字、激进、忠诚、合法性、权威、生活水平、人口增长、科技点、陆军战力、
士气、人力、威望、失业、官僚效能、官僚上限、建造速度、市场接入、交通基础设施与行政能力。
