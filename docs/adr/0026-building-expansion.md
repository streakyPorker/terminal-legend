# 建筑扩张与统一基础设施

- Status: accepted（F1–F7 已实现，World v11：F5 统一基础设施见下 §3 与 plan 0011 §7.6；F6 见 §4；F7 分批校准见 plan 0011 §7.8）
- Fixes: 建筑名册过窄、工厂一包七货导致**逐建筑利润率读不清**；基础设施「交通」含义不清、只有铁路/港口两来源。
- Depends on: `docs/plans/0011-building-expansion.md`、ADR 0021（建筑配方单一真源）、ADR 0022（利用率与利润投资）、ADR 0010/0012/0013（营造所与建造能力）、ADR 0005（不做存档兼容）

## 背景

### 名册太窄，工厂一包七货

World v10 的建筑只有 9 类：农场、矿场、工厂、铁路、港口、大学、兵营、官署、营造所。
其中两类是「多合一」的：

- `mines`（矿场）一座同时产煤、铁、木三种货；
- `factories`（工厂）一座同时产布、成衣、酒、家具、机械、军械、奢侈品**七种货**。

`BUILDING_RECIPES`（ADR 0021）把这一包输出写在一行里，`buildingProfits`（ADR 0021/0022）
的利润率也是按**这一整包**算的。于是玩家（和 GM）看到「工厂盈利 15.8%」时，**无法回答
「到底哪一条产品线在赚、哪一条在亏」**——一条亏钱的产线会被其他产线掩盖，配方调参也没有
清晰的着力点。用户的要求很直接：**单产（或少数产）建筑**，让每类建筑的盈利能力可见、可调。

### 基础设施只有一半

今天只有 `transportInfrastructure`（0–100）一个「交通」量：铁路建成 +3、港口只加市场接入
（`completeBuilding`），生产门控是 `0.6 + 交通 / 160`（`engine/config/blocks/gates.ts`）。
用户要的是一个**统一的基础设施概念**：铁路、港口、**运河、电报**都生产它；**每类建筑**都要
消耗它（`infrastructureNeed`）；供给不足时给**线性生产 debuff**；它自身每月要烧**原料与服务**
（服务来自现有的官署/大学）。不是另起一个平行池子，而是把「交通基础设施」升级成唯一的
「基础设施」。

### 商品语义

现有 `GOODS.iron.name` 是「钢铁」，而产出它的资源 `RESOURCE_MAP.iron` 叫「铁矿」——名不副实。
用户决定：**铁矿建筑产出「铁矿石」；钢铁厂用「铁矿石 + 煤」炼「钢铁」**；机械厂/兵工厂/铁路/
家具厂等把原来消耗 `iron` 的地方改消耗**钢铁**。相关商品就是「铁矿 + 钢铁」两件，**新商品
集保持最小**：本次只加 `steel` 一件，其余全部复用既有货。

## 决定

### 1. 建筑名册（World v11）

**保持不变的 8 类**：农场、铁路、港口、大学、兵营、官署、营造所（军营即现有兵营，保留）。

**拆分`mines` → 三个单产采掘建筑**：

| id | 名称 | 产出 |
| --- | --- | --- |
| `coalMines` | 煤矿 | `coal` |
| `ironMines` | 铁矿 | `iron`（= 铁矿石） |
| `lumberMills` | 伐木场 | `wood` |

**拆分`factories` → 七个单产/少产工业建筑**：

| id | 名称 | 产出 | 备注 |
| --- | --- | --- | --- |
| `textileMills` | 纺织厂 | `fabric` + `clothes` | 两产（纤维 → 成衣同链） |
| `furnitureWorks` | 家具厂 | `furniture` | |
| `distilleries` | 酿酒厂 | `liquor` | |
| `machineryWorks` | 机械厂 | `machinery` | 消耗钢铁 |
| `steelMills` | 钢铁厂 | `steel` | 消耗铁矿石 + 煤 |
| `arsenals` | 兵工厂 | `arms` | 消耗钢铁 |
| `luxuryWorks` | 奢侈品厂 | `luxury` | |

**新增 5 类**：

| id | 名称 | 作用 |
| --- | --- | --- |
| `schools` | 学校 | 初等教育（与「大学」= 高等相对）；产服务/促识字 |
| `canals` | 运河 | 基础设施供给者 |
| `telegraphs` | 电报 | 基础设施供给者 |
| `forts` | 要塞 | 军事；小量军械产出（详见计划） |
| `navalYards` | 船坞 | 造舰/机械产能（详见计划） |

`types/index.d.ts` 的 `BuildingId` 联合类型、`BUILDINGS`、`BUILDING_RECIPES`、`BUILDING_TIME`、
`CAPACITY_COST`、`INVESTMENT_DEMAND`、`BUILDING_OUTPUT`、`BUILDING_COST_MULTIPLIER/ADDEND`、
`COUNTRY_SEEDS` 全部按新名册重写（计划的 F2–F4 里程碑）。

### 2. 商品：`iron` → 铁矿石，新增 `steel`

- **保留 `iron` 的 id**（最小改动），把其**显示名改为「铁矿石」**（`GOODS.iron.name`）。
- **新增 `steel`（钢铁）** 一件商品。
- `RESOURCE_MAP.iron`（铁矿禀赋）产出 `iron`（铁矿石），语义自洽。
- `steelMills` 消耗 `iron`（铁矿石）+ `coal` → 产出 `steel`。
- 机械厂/兵工厂/铁路/家具厂/营造所等把配方里**原来消耗 `iron` 的地方改消耗 `steel`**。
- `steel` 不是消费品：`SUBSISTENCE.steel = 0`、`INCOME_ELASTICITY.steel = 0`（两者都是
  `Record<GoodId, number>`，必须补键）；`GOVERNMENT_DEMAND.construction` 的 `iron` 改 `steel`；
  `TRADABLE_GOODS` 加入 `steel`（`engine/trade.ts`）。
- **新商品集保持最小**：本次只加 `steel`；「铁矿 + 钢铁」两件即用户所指的相关商品。
  其余配方一律复用既有货（`fabric`/`wood`/`coal`/`machinery`/`arms` 等）。

数值（基价、系数）全部为**提案，可调**，见计划 §3。

### 3. 统一基础设施（一个国家级概念）

把 `transportInfrastructure` 升级为唯一的**基础设施**：不是新开一个池子，而是同一个数，
含义更宽、来源更多、有需求侧。

**供给**（每月，每座）：

| 建筑 | 供给 |
| --- | --- |
| 铁路 `railroads` | 2.5 |
| 港口 `ports` | 1.1 |
| 运河 `canals` | 1.6 |
| 电报 `telegraphs` | 0.7 |

> 上表为 **F7 校准值**（原提案 3.0/1.5/2.0/0.8 已下调），使 1836 十国基础设施 ratio 全部 ≥1、
> 84 月有国家自然跌破 1；详见 plan 0011 §7.8。

**需求**（每月，每座；`infrastructureNeed`）：**每一类建筑**都有一个需求值，重工业/采掘高、
服务/公署低。提案表见计划 §4（可调）。

**平衡与 debuff**：

```
ratio = 供给 / max(ε, 需求)
基础设施乘数 = ratio ≥ 1 ? 1 : clamp(ratio, 0.35, 1)     // 线性短缺 debuff
每座产出 *= 基础设施乘数                                   // 作用于所有建筑
```

- **统一池**：一个国家级 `infrastructure` 供给对全部建筑的类型需求求和，**没有分池**。
- **线性**：供给只有一半 → 乘数 0.5；供给充足（≥ 需求）→ 无 debuff（=1）。
- **存储**：月末由建筑数算出 `基础设施水平 = clamp(100 × ratio, 0, 100)`，写入
  `econ.transportInfrastructure`（**F5 已定：字段名与 ModifierStat 保留，仅显示名改「基础设施」**——
  避免 v11 存档形状断裂；该字段从此是**派生**值，不再累加），生产在
  **下月**读取，沿用 ADR 0022 的「生产读存储值、留一个月滞后」纪律（建筑数是结构量，
  本身不读当月价，滞后只为与利用率一致）。
- **旧门控退场**：逐配方的 `gates.infrastructure` 标志与旧的 `0.6 + 交通/160` 曲线
  **不再作为生产门控**（被上面的统一乘数取代）。是否保留一个「过剩奖励（>1）」**待定**，
  本 ADR 取**只罚不奖**的简单式。
- **消耗（维护）**：基础设施每月消耗**原料 + 服务**，服务来自现有官署/大学——
  即给 `computeDemand` 加一块与基础设施规模挂钩的中间需求。提案：

  ```
  吞吐维护 = 供给 × { wood: 0.01, coal: 0.015, services: 0.02 }   // 与运量走
  行政维护 = (水平 / 100) × { services: 0.01 }                     // 与规模走
  ```

  数值**可调**。v1 里维护**不反向门控供给**（只是需求），是否让原料短缺拖累基础设施**待定**。

**注意**：铁路/港口/运河/电报**不产可贸易货**，在货物账本上是**成本中心**（`buildingProfits`
营收近似为 0），它们的回报是**基础设施流**与（铁路/港口的）市场接入，因此**不纳入
「逐建筑利润带」gate**（与今天铁路/港口/营造所被排除同理）。

### 4. 建筑解锁字段（前瞻，非科技树）

建筑定义新增可选字段：

```ts
type BuildingUnlock = { techLevel?: number }
type BuildingDef = {
  name: string
  cost: number
  note: string
  unlock?: BuildingUnlock
  infrastructureNeed: number
}
```

- **当下所有建筑都解锁**（本切片没有科技树）：`unlock` 一律缺省或为空对象。
- 它是 **plan 0005（科技树）** 的前向兼容占位：将来 `unlock.techLevel` 生效时，
  `build` 动作（`engine/actions.ts`）在该国 `tech.level` 低于阈值时拒绝。
- **本次就把校验加进 `build` 动作**：`unlock?.techLevel !== undefined && tech.level < 阈值 → 拒绝`。
  因当前全部缺省，行为与今天一致（无建筑被挡）。

### 5. 单产原则与利润带

- **原则**：每类建筑**单产**（少数链条允许两产，如纺织厂纤维→成衣）。
- 每类**产货**建筑获得一个**目标利润带**，并**加入 `tests/economy-recipe-calibration.test.ts`**
  的 gate（`buildingProfits` 口径）。
- **分批调参**：校准**分批**进行（一个国家/一组建筑一带），不是一次性全调，见计划 F7。
- 基础设施提供者与营造所为成本中心，不进利润带。

### 6. 世界版本 → v11

结构改动（名册、商品、基础设施口径），按 **ADR 0005** 旧存档直接拒绝；`createWorld` 的
`version` 与 `save.ts` 的 `CURRENT_WORLD_VERSION` 一并升到 **v11**。

## 代价

- **`COUNTRY_SEEDS` 大改**：每个种子的 `buildings: Record<BuildingId, number>` 必须按新名册
  重写——矿场 35 座要拆到煤矿/铁矿/伐木场，工厂 20 座要拆到七个工业建筑，还要给新建筑
  赋初值。这正是「拆分」的真实成本。
- **必须重新校准**：名册、商品语义与基础设施口径都变，B5 建立的工厂毛利带与两侧贸易基线
  都会漂移，需要 F7 的分批校准重建。
- **`iron` 语义变更**：同一个 id 从「钢铁」变成「铁矿石」，凡读 `iron` 的配方/税收/贸易/
  事件文案都要跟着改（机械厂等改吃 `steel`）。保留 id 降低了改动量，但**语义断层**必须在
  提交信息与本文里写清。
- **存档断裂**：v10 存档不可用，需 `/v3 new`。
- **一次性行为变更**：利用率/利润反馈、私人投资、贸易基线都会变，测试需按新名册重定。

## 暂不覆盖

- **科技树解锁**：`unlock` 只是前向占位；真正的科技树是 plan 0005，不在本 ADR。
- **更多商品**：本次只加 `steel`；「按需加，不要过于膨胀，先维护一个最小可用集」。
- **更多服务/公共建筑**：学校只做初等教育的最小切片；进一步的教育/卫生/司法建筑未列。
- **基础设施维护反噬供给**：v1 维护只是需求；原料短缺是否拖累基础设施**待定**。
- **过剩奖励**：基础设施「供过于求」是否给生产奖励**待定**，本 ADR 只做短缺惩罚。
- **分池基础设施**：明确**不做**——一个国家级统一池。

## 不变量（要求保持）

- `C+I+G+NX === GDP`；全部金币守恒恒等式；贸易路线金币恒等式。
- 60/120 月确定性；鸦片危机门（plan 0004 §4.1 的 ≥2 单位/月、≥20% 来自英国）。
- `wages + profits` 在 `[0.5, 1.5] × realGdp` 内；`Σ buildingProfits.wages === 全国 wages`。
