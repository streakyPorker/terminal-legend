# 政策数值由 LLM 自由提议，不设硬上限

- Status: accepted

政策提议的数值（绝对值与百分比）由 LLM 自由给出，引擎只做类型检查、记录与结算，不设每月硬上限；失衡时依靠天命工具或重开处理。

原因：过早的数值边界会把 LLM 的拟人化决策压回模板，当前阶段更需要观察哪些政策组合有趣。

代价：单条政策可能把世界改穿。若失衡成为常态，再引入“按幅度计价 + 月度政策预算”，并按 ADR 0003 的边界把数值重新收进引擎。

## 2026-10-19 修订（第 2 轮深度体验后）

失衡已经成为常态：5 点权威的永久 `gdp +100000%` 被接受，三条不同名的 `+50%` 可叠加到 4.2 倍。因此提前启用本 ADR 预留的方案：

- 权威成本按 `|value| × 持续月数` 计价（`required = round(weight × 0.2)`，上限 40），取玩家/模型申报成本与计价成本的较大值。
- 单条效果 `|value| ≤ 200`；持续月数上限仍为 240。
- 同类**永久**政策（相同 stat + stack）覆盖而不叠加；限时政策仍各自占槽并到期。
- 第 3 轮追加：政策每月收取 `成本/48` 的权威维护费，付不起时最早的政策中止；`gdp`/`consumption`/`demand`/`production` 与所有 `*Output`/`*Demand` 的单条百分比上限 100%。
- 暂不引入月度政策预算；先观察计价 + 维护费 + 上限是否足够。
