# GM 明细接口：v3_inspect 与 v3_forecast

- Status: accepted（World v7，纯读取，不升版本）
- Implements: plan 0006 的第一批

## 背景

试玩里反复出现“为什么变了”的问题：GDP 单月大跌（PT-016）、失业率与劳动利用率口径
打架（PT-008/023）、税入随租金缩放（PT-026/028）、出口为零没有原因（PT-010）。
只靠 `v3_status` 的一行总账无法回答，而 GM 又被禁止读存档、也不该靠读源码解释。

## 决定

### 1. `v3_inspect`

只读分区查询，`section` 取：

| 分区 | 内容 |
| --- | --- |
| `economy` | GDP 分解（C+I+G+NX）、各商品现价/基准/缺口、工资与利润 |
| `fiscal` | 收入与支出逐项、国库/国债、利率、债务压力、私人逆差、租金 |
| `labor` | 失业率、原始需求/劳动力、结构性缺口、工资、就业基础 |
| `trade` | 出口/进口总额、按商品与伙伴的货值、关税、进口容量 |
| `construction` | 建造力构成（营造所 + 补贴）、队列、私人流转、租金 |
| `military` | 陆军/海军/士气/人力/质量、军费等级、战争 |
| `history` | 最近 12 个月的 GDP/C/I/G/失业/收入/支出/关税/国债 |

历史序列在每月结算时写入 `econ.history`（新增 c/i/g/income/expense/unemployment/debt/tariff）。

### 2. `v3_forecast`

按上月账本推算下月现金流：收入（含预计租金）、支出（把国有建设换成
`已分配建造点 × 0.2`，加上补贴）、净额与结算后国库。明确标注“计划值”，
贸易与事件会让它偏移。

### 3. 边界

- 两个工具都只读，不写世界。
- 秘书也可以调用（加入其工具列表）；工具不可用时，以简报数字为准，禁止编造。
- 存档与引擎源码仍不对 GM 开放。

## 代价

- `econ.history` 每月多存 8 个数字，可忽略。
- 预测是静态外推，不模拟下月贸易与事件；月报里必须保留“计划值”的免责声明。
