### PT-001 全球粮食过剩，农产品没有世界市场

- 日期：2026-10-20
- 世界：1836.01–1836.02
- 存档：seed=9100 / 玩家=QING（24 个月无玩家操作基线）
- 现象：大清粮食、木材、成衣都大量过剩，但 24 个月里出口始终为 0。
- 数据：24 个月基线中，粮食每月都是 10 国全部 offer、0 个 bid；大清第 1 月粮食产量 2692、需求 195（13.8 倍）；十国粮食生产/需求比在 6.96–24.77 之间。
- 判断：不是价格或关系问题，而是**全球农产品结构性过剩**。贸易清算只匹配“有 bid 的进口国”，所以大清永远卖不出去。根因是农场系数（1.05/月/座）相对 Stone-Geary 粮食需求过高。
- 修复：32e624b（E1 第一轮）把农场粮食系数降到 0.30、农场木材降到 0.04、矿场木材降到 0.04，并让工厂消费粮食（×1.0）制造工业国需求。24 个月基线：粮食 bid 24/24、大清粮食或木材出口 24/24。
- 关联：0007-E1
- 状态：fixed（32e624b）

### PT-002 成衣/酒/家具/军械同样全球过剩

- 日期：2026-10-20
- 世界：1836.01–1836.02
- 存档：seed=9100 / 玩家=QING
- 现象：除粮食外，成衣、酒、家具、军械也全部是 offer、没有 bid。
- 数据：24 个月中，clothes/liquor/furniture/arms 的 bid 月份均为 0，offer 月份均为 24；十国生产/需求比：成衣 2.3–11.4、酒 1.4–7.3、家具 1.5–12.6、军械 1.1–5.5。
- 判断：消费品与军工也系统性过剩；全球贸易只剩煤/铁/布/木材/鸦片等少数商品，分工不成立。
- 备注：32e624b 的 E1 第一轮只修了粮食/木材/机械；成衣、酒、家具、军械仍是全球 0 bid。留待第二轮决定是下调产出系数，还是承认这些商品以本地自给为主。
- 关联：0007-E1
- 状态：open（第二轮）

### PT-003 机械全球短缺，没有任何 offer

- 日期：2026-10-20
- 世界：1836.01–1836.02
- 存档：seed=9100 / 玩家=QING
- 现象：机械 24 个月全部是 bid、0 个 offer，任何国家都买不到机械。
- 数据：十国机械生产/需求比 0.37–0.88；最后的全球 bid 合计 34.3、offer 0。
- 判断：工厂机械产出（0.09/座/月）低于需求（每座工厂 0.18 + 建设需求），所有国家都短缺；机械无法通过贸易获得，只能自建工厂，贸易层少了一条重要链路。
- 修复：32e624b（E1 第一轮）把工厂机械产出翻倍到 0.18/座/月；24 个月基线机械 bid/offer 均为 24/24，英法普澳美可向大清等低技术国出口。
- 关联：0007-E1
- 状态：fixed（32e624b）

### PT-004 贸易缺口转外债，净资产 13→0

- 日期：2026-10-20
- 世界：1836.02
- 存档：实际存档（玩家已执行税 20/建设 18）
- 现象：首月账面净额 +3.0 金，净资产却从 13 掉到 0。
- 数据：进口 16.0 金、出口 0；贸易缺口 16.0 单独扣减净资产；进口构成：煤 7.9、布 4.7、奢侈品 1.4、鸦片 1.2、铁 0.8 等。
- 判断：支付能力 = 出口收入 + 私人资本 + GDP×3% ≈ 15 金；出口为零时，进口几乎全部转为外债。机制本身可解释，但玩家看不到支付能力与缺口分解，体验上像“钱凭空消失”。
- 关联：0007-E2、0006
- 状态：open

### PT-005 建造队列按工期排序，铁路长期 0%

- 日期：2026-10-20
- 世界：1836.02
- 存档：实际存档
- 现象：同一批项目里，矿场 65%、官署 52%、铁路 0%；铁路长期拿不到拨款。
- 数据：`settleConstruction` 按 `monthsLeft` 升序拨款；现金紧张时短工期项目先吃满预算，8 个月工期的铁路只能分到零头。
- 判断：玩家无法表达优先级，长工期项目会被静默饿死；应改为入队顺序、比例分配或最低保留拨款，并在面板显示“本月实拨”。
- 关联：0007-E3
- 状态：open

### PT-012 贸易缺口使国库为负，国有建设静默停摆

- 日期：2026-10-20
- 世界：1836.03
- 存档：实际存档
- 现象：月报写“收入 38.7 / 支出 26.5 / 净 +12.2”，国库净资产却是 −2.9；国有工程进度完全没有变化。
- 数据：贸易缺口 15.1 单独扣减净资产；`settleConstruction` 用 `Math.max(0, treasury)` 作为现金上限，国库为负时国有建设实付 0；队列仍显示矿场 65%、官署 52%、工厂 0%、铁路 0%，没有任何“因国库为负暂停”的提示。
- 判断：机制本身正确（不能透支建设），但月报与面板没有把“贸易缺口吃掉了建设现金”说出来；玩家会以为工程在正常推进。需要 E2 的支付能力/缺口可见化，以及 E3 的“本月实拨/暂停原因”显示。
- 修复：2757834（ADR 0007）取消“净资产为负即停摆”，国有建设可赤字融资到 3× GDP 重组底线；债务/GDP ≥ 25% 起按比例施加收入、建设速度、合法性与月息 debuff，并在 `v3_status`/HUD 显示债务压力档位。E2/E3 的月度实拨提示仍待补。
- 关联：0007-E6、ADR 0007
- 状态：fixed（2757834）

### PT-013 收入 > 支出，净资产仍下降：贸易缺口在账外

- 日期：2026-10-20
- 世界：1836.03
- 存档：实际存档
- 现象：月报“收入 38.7、支出 26.5、净 +12.2”，净资产却从 0 掉到 −2.9，看起来账不平。
- 数据：贸易缺口 15.1；净资产实际变动 = 净 +12.2 − 贸易缺口 15.1 = −2.9。
- 判断：ADR 0006 有意把私人部门的贸易缺口放在财政支出之外，直接扣减净资产；这是 v7 的设计。但月报/HUD 只把“净额”和“净资产变动”并排显示，没有把缺口作为中间项，玩家会认为收入 > 支出不应负债。另一个更深的问题是**结算顺序**：进口清算发生在本月利润转入私人资本之前，支付能力只算期初私人资本；期末显示的 27.6 私人资本无法回头支付当月进口，于是缺口持续转为国债。
- 修复：c427661（ADR 0008）把私人进口逆差从国库剥离：`privateCapital` 允许为负，负值即私人外债；`treasury` 只受收入/支出影响，`tradeGap` 仅作展示。E2 的拆账显示仍待补。
- 关联：0007-E2、0007-E4、ADR 0008
- 状态：fixed（c427661）

### PT-014 自由贸易把关税降到 0，出口不征税

- 日期：2026-10-20
- 世界：1836.03
- 存档：实际存档
- 现象：推行自由贸易后关税变成 0%；出口不征税，国库只从进口收税；到岸价只含进口国关税。
- 判断：默认关税不应为 0（约 5%），且出口也应能征税；伙伴排序、支付能力与金币结算都应按“出口国出口税 + 进口国进口税”的真实价格。
- 修复：c427661（ADR 0009）让同一个 `tariff` 同时征收出口税与进口税；到岸价乘 `(1+出口税)×(1+进口税)`；自由贸易降 8 点但**下限 5%**；当前局关税已调到 5%。
- 关联：ADR 0009
- 状态：fixed（c427661）

### PT-015 债务 50 就触发「财政崩溃」，与债务/GDP 平滑压力冲突

- 日期：2026-10-20
- 世界：1836.06
- 存档：实际存档
- 现象：债务 52.1、GDP 579.5（仅 9%），状态里却挂着两条「财政崩溃」修正（收入 −10%、合法性 −3）。
- 数据：`thresholds.ts` 的 `bankrupt` 规则条件是 `treasury <= 0 && debt >= 50`，与 ADR 0007 的“债务/GDP 25% 起平滑加压”冲突；绝对 50 金对大国过严。
- 修复：c427661 删除 `bankrupt` 规则；平滑债务压力负责 25%–2×，`debt-crisis` 保留在 1.5× GDP，3× GDP 重组底线不变。
- 关联：ADR 0007、ADR 0009
- 状态：fixed（c427661）

### PT-016 月报 GDP 单月 −93.8，缺少逐月分解

- 关联：0007-E2、0007-E4
- 状态：open

### PT-017 建造队列没有建造能力/营造建筑，只有金本位预算

- 日期：2026-10-20
- 世界：1836.08
- 存档：实际存档
- 现象：玩家问“工厂能提高建造能力么”；建造队列一栏只显示每月金币和剩余工期，没有建造力/建造能力，也没有一类消耗资源、产出建造力的建筑。用户要求：每个槽位消耗指定建造能力，按队列往下排；私人建造不占国有营造所；国有建造力闲置时可租给私人并获得收入。
- 判断：旧模型把建造能力等同于 `spending.construction × 0.8` 的金币预算，缺少实物投入与槽位约束。
- 修复：2bc61ca（ADR 0010）新增「营造所」，消耗木材/粮食/铁产出建造点；项目按入队顺序消耗建造点；国有优先，私人自建 50% 并可租用国有闲置点（0.3 金/点）；状态与面板分栏显示建造能力、国有需求/分配/闲置和私人建造；旧 v7 存档自动补营造所。
- 关联：0007-E7、ADR 0010
- 状态：fixed（2bc61ca）


### PT-018 建造槽位上限/满额完工规则不明确

- 日期：2026-10-20
- 世界：1836.08
- 存档：实际存档
- 现象：第一版只给了“每槽最多 15 点建造力”的扁平上限，项目仍按 `BUILDING_TIME` 分摊工期；玩家要求每槽最多 15 座、单槽上限 15×单座建造点、满额 1 个月造完，且每月订单数量不限，盈余给私人。
- 判断：扁平点数上限与“按建筑需求分配”冲突；工期应由建造点决定，而不是再叠一层月份计时。
- 修复：67c13de（ADR 0011）把 `v3_action build` 的 count 上限设为 15；单槽点数上限改为 `15 × CAPACITY_COST[building]`；新建国有/私人项目 `monthsLeft = 1`、`monthlyCost = 全额造价`；删除 8 个项目上限；私有槽位仍自建 50%、可租用国有闲置点。
- 关联：0007-E7、ADR 0010、ADR 0011
- 状态：fixed（67c13de）


### PT-019 建设拨款已不限制进度，界面仍显示可调

- 日期：2026-10-20
- 世界：1836.08
- 存档：实际存档
- 现象：ADR 0011 后，国有槽位由建造点与 3× GDP 债务空间决定，`spending.construction` 不再参与结算；但面板与 `v3_action spending` 仍显示“建设支出”并可调整。
