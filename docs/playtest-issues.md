### PT-033 统一基础设施的短缺 debuff 手感未试玩

- 日期：2026-10-21
- 世界：待开局（World v11，建议 seed 9100）
- 存档：待建
- 现象：plan 0011 F5/F7 把「交通基础设施」升级为**统一池**——铁路/港口/运河/电报**供给**，
  全建筑按 `infrastructureNeed` **需求**，`ratio = 供给/需求 < 1` 时对**所有建筑产出**施加
  `clamp(ratio, 0.35, 1)` 的**线性 debuff**（只罚不奖）。设计意图是「1836 不预触发，
  工业化推进而基建不扩建时 debuff 自然显现」，**但整段手感尚未被真人试玩验证**。
- 数据：F7 校准后 1836 十国 ratio ∈ **[1.10, 2.30]**（不预触发）；84 月 QING 0.87、PRU 0.54、
  RUS 0.66、AUS 0.51（最低 0.51，未触 0.35 地板）。
- 判断：数值上「不预触发 + 后期自然跌破 1」成立，但**玩家是否感知得到、是否知道要补基建、
  debuff 是否过轻/过重、是否需要提示**均未验证。
- 建议：试玩观察——中期是否出现「产出莫名下降」而无解释；`v3_inspect economy` 的
  「统一基础设施」行是否足够显眼；跨越 `ratio<1` 时是否需要一个提示或事件。
- 关联：0011 F5/F7、ADR 0026
- 状态：open（待试玩）

### PT-053 「生产 +50%」修正生效后 GDP 不升反降（564.2 → 531.9）

- 日期：2026-10-24
- 游戏内日期：1836.01 → 1836.02
- 存档/种子：新局 QING（1836.01 起）
- 现象：以天命注入 `生产 +50%（percent，240 月）` 修正，
  `v3_inspect modifiers` 确认生效；推进一月后 GDP **564.2 → 531.9（-32.3，-5.7%）**，
  生活水平 28 → 27、失业 6.0% → 7.5%。
- 数据：
  - GDP 分解：消费 549.8 → 543.1、投资 0 → 0、政府 14.4 → 14.9、净出口 0 → **-26.2**；
  - 物价普遍下行：粮食 0.72 → 0.61（↓61% 基准）、木材 0.89 → 0.78、成衣 2.67 → 2.41；
  - 私人部门贸易逆差 26.4 金，而「私人资本 0.0 / 私人外债 0.0」——逆差没有可见的融资方；
  - 劳动原始利用率仍为 **3.9%**（需求 965 万 / 劳动力 2.5 亿）；
  - 收入 18.6 / 支出 26.4，净 -7.8，国库 13.0 → 5.2。
- 判断：**待定，但至少是「反直觉且无法从工具解释」**。两种可能：
  1. GDP 以**市价**计量（C+I+G+NX），产出增加只压低了价格、没抬名义值，再叠加贸易逆差，
     数字自然下行——经济上自洽，但与「生产 +50%」的字面预期严重不符；
  2. 「生产」修正只作用于**潜在产能**，而需求约束下实际产出不变／变价不变量的口径不一致。
  另外，私人贸易逆差 26.4 金在私人资本为 0 时如何结算，工具没有给出解释（疑似私部门外债即时计入但未显示）。
- 建议：明确 GDP 口径（实际 vs 名义）并在 `v3_inspect economy` 标注；若为名义值，
  生产类修正的说明应提示「需求不足时主要体现为降价」；补上私人贸易逆差的融资方显示。
- 关联：`engine/economy.ts`（GDP 与价格结算）、`engine/trade.ts`（净出口/私人逆差）、
  `engine/modifiers.ts`（production 修正的落点）、计划 0007-economy-polish 的 E1–E5。
- 优先级：**P1**
- 状态：**open**

### PT-054 天命修正无法撤销，只能叠加反向修正对冲

- 日期：2026-10-24
- 游戏内日期：1836.01
- 存档/种子：新局 QING（1836.01 起）
- 现象：玩家要求撤回刚施加的「生产 +40%」永久修正。`v3_cheat` 的 `modifier` 只有「施加」语义，
  没有 remove/clear/delete；`v3_inspect modifiers` 只读，也无撤销入口。GM 只能再叠一条
  `stat=生产, stack=percent, value=-40` 的反向修正来对冲。
- 数据：`v3_inspect modifiers` 现并列两条 `stat=生产`——`+40%`（柳大飞新政·百工振兴）与
  `-40%`（撤回·百工振兴（与+40%对冲）），净效果取决于 percent 是否**加性**叠算；
  手册 §3/§9 与工具输出均未说明 percent 多条同 stat 时是相加还是相乘。
- 判断：**工具能力缺口 + 口径缺失**。撤销应当是一等操作（按 label/id 删除或清空某国 cheat 修正），
  否则每条误施的修正都会永久留在列表里；同时 percent 的叠算规则需要写进手册，否则
  「对冲是否真的等于 0」无法从工具判定。
- 建议：`v3_cheat modifier` 增加 `action=remove`（按 label 或 id）或 `action=clear`；
  `v3_inspect modifiers` 每行补一个稳定 `id`；手册 §9 补一行 percent 叠算口径。
- 关联：`hooks/tools.ts`（`v3_cheat` modifier 规格）、`engine/modifiers.ts`、手册 §3/§9。
- 优先级：**P2**
- 状态：**open**

### PT-055 「市场接入 +20（flat）」把建造力放大 ~19 倍（0–1 标量未钳位）

- 日期：2026-10-24
- 游戏内日期：1836.01
- 存档/种子：新局 QING（1836.01 起）
- 现象：`v3_inspect construction` 显示 **1022.5 点/月**，其构成只有「营造所 12 座 + 建设补贴 2 级 × 1.5」，
  折合 **≈85 点/座·月**；手册 §4.6 写的是 **每座每月 4 点**，差 **21 倍**。

  4. 读取面：`v3_inspect fiscal` 的消费税一行要能展开到「商品 × 税率 × 税额」，
     能看出哪些商品是定制档、哪些走兜底；
  5. 只对**最终消费**计税的既有口径不变（中间投入不征），合规侵蚀（>25% 起）按**逐商品税率**判定。
- 关联：ADR 0023、`engine/fiscal.ts`（`taxBaseRevenues` / `taxCompliance`）、
  `engine/data/goods.ts`（`CONSUMER_GOODS`）、`hooks/tools.ts`、`engine/inspect/fiscal.ts`、§4.7。

### PT-074 看不到他国的税率与基本经济数据

- 日期：2026-10-25
- 游戏内日期：1839.02
- 来源：玩家问「其他国家的土地税是多少」，并要求「各种基本经济数据都要能查到」
- 现象：`v3_inspect` 除 `log` 外一律读**玩家本国**，`country` 参数只用于 `log` 的行过滤：
  能看见英国的国债 477.1，却看不见它收几成关税；无法横向判断「大清的税率是不是偏低」。
- 数据（1839.02 实测，见修复后的输出）：三大内税各国完全相同——
  土地 2% / 企业 2% / 消费 3%；差异全在**关税**（英 5 / 普 8 / 清 10 / 俄 15 / 法 18 / 美 20）
  与**征收效率**（清 111.9%，英 43.4%，法 49.9%，俄 42%，普 38.8%，美 46.1%）。
  即「大清土地税低」的前提本身不成立——**所有列强的土地税率一样，差的是税基（农田座数）与征收效率。**
- 判断：**情报缺口**。横向量本是玩家做决策的基本材料，不该只有本国可见。
- 修复：
  1. `engine/inspect/index.ts` 把 `subject` 泛化到所有「单国」分区
     （economy / market / fiscal / labor / trade / routes / buildings / construction /
     military / pops / diplomacy / tech / history），缺省仍是本国；
  2. `log` 保持原语义：`country` 是日志行过滤，不是主体选择；
  3. 未知国家 id 返回「未知国家「X」」并列出可用 id，不再静默回落到本国；
  4. `hooks/tools.ts` 的 `country` 描述与手册 §3 同步；
  5. `tests/inspect.test.ts` 增加 4 个用例（他国税率为准、13 个分区主体生效、
     未知 id、缺省本国），全量 **541 项通过**。
- 关联：`engine/inspect/index.ts`、`hooks/tools.ts`、`docs/gm-handbook.md` §3、PT-073。
- 优先级：**P2**
- 状态：**fixed（待提交）**
